# Governance lifecycle

| Stage | What happens | Control |
|---|---|---|
| Intake | A request arrives from the website | Server-side bot check; required fields; consent recorded with a timestamp |
| Assessment | Structured leadership session and evidence review | Fixed, versioned instrument; responses recorded per question |
| Classification | Dimension results, composite score, maturity band, risk signals | Formulas tested at ceiling, floor and mixed conditions before use |
| Human review gate | AI-drafted material is checked and approved | Nothing is issued without named approval |
| Approval and issue | Score set to Active with a valid-until date | Valid for 12 months from the reading date |
| Ongoing oversight | Re-assessment reminders, automatic lapse, supersession by a newer reading, withdrawal under defined conditions | Every status change written to an append-only log |
| Relying-party requests | Third parties ask whether a score is current | Answered only after the assessed firm's consent is confirmed; the letter states status, not findings |

## Score status model

| Status | When |
|---|---|
| Active | Issued at debrief |
| Lapsed | Automatically, once the validity period has passed |
| Superseded | A newer full reading of the same entity is issued |
| Withdrawn | Only under conditions written into the engagement terms, for example material misrepresentation |
